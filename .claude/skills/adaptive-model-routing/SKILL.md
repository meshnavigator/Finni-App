# Adaptive Model Routing

Выбирай модель не для всего пользовательского запроса, а для каждого
самостоятельного пакета с собственными scope, критериями готовности и verify.
Политику проекта читай из `.project-kit/model-routing.json`, если она доступна.

## Шлюзы

1. При явном `DIRECT` передай управление `$direct-model-routing` и прекрати
   adaptive routing.
2. При `SOLO`, «без субагентов», «без делегирования» или «только основной поток»
   не создавай агентов.
3. Иначе применяй профиль `BALANCED`, если пользователь не выбрал
   `ADAPTIVE FAST` или `ADAPTIVE DEEP`.

## Ценовой шлюз Astra

Если подходящим исполнителем является Astra, не запускай её сразу. Сначала
сообщи пользователю reasoning, пакет работы и краткую причину, затем спроси:
`Разрешаете запустить Astra для этого пакета?` Дождись явного подтверждения;
оно действует только для названного пакета.

При отказе маршрутизируй пакет на Sol High, если пользователь не выбрал другой
вариант. Если пользователь сам открыл основную задачу на Astra через интерфейс
Codex, этот ручной выбор считается подтверждением для текущей задачи и не
требует повторного вопроса перед каждым сообщением.

## Выбор модели

- GPT-6 Luna High: механическая, локальная, хорошо определённая работа с низким
  риском и детерминированной проверкой.
- GPT-6 Sol Medium: стандартная реализация и диагностика, в том числе несколько
  связанных модулей без ключевого продуктового решения.
- GPT-6 Sol High: архитектура, интеграция пакетов, неоднозначные инженерные
  компромиссы и финальная сборка результата.
- GPT-6 Sol XHigh: особенно сложная архитектура или review, когда Astra не
  требуется.
- Astra: максимальная сложность или цена ошибки — критичная численная логика,
  безопасность, миграции, противоречивые требования, длинный горизонт решения.

Повышай reasoning по неопределённости и цене ошибки, а не по длине запроса.
Не используй фиксированную лестницу Luna → Sol → Astra.

## Профили

- FAST: предпочитай Luna High или Sol Medium, без автоматической эскалации.
- BALANCED: выбирай минимально достаточную модель; допускается одна эскалация
  пакета после доказанного концептуального блокера.
- DEEP: используй Sol High/XHigh; Astra — только для предельного риска после
  отдельного подтверждения. Независимое review проводи, когда цена скрытой
  ошибки это оправдывает.

## Ограничения

- Основной поток сохраняет пользовательское намерение, границы задачи и
  ответственность за финальный результат.
- Один пишущий агент на одну рабочую директорию. Параллельная запись допустима
  только в отдельных worktree с заранее определённым объединением.
- Разрешён один точный correction той же модели; после него либо одна
  обоснованная эскалация, либо возврат задачи основному потоку.
- Не привлекай более сильную модель, если декомпозиция делает пакет однозначным
  и низкорисковым.

Для каждого делегированного пакета кратко фиксируй `ROUTE`, `REASON` и
`ESCALATION`. Пользователю показывай это только в сжатом итоговом отчёте.
