# Sprint 0 — порядок выполнения и gates

> Sprint 0 переводит проект из governance baseline в проверяемый Android bootstrap. Статус спринта: **В РАБОТЕ** с 2026-09-16. S0-005 закрыта как partial 2026-09-17: APK собран, но физический runtime-gate перенесён в S0-006. Повторная стековая проверка S0-002 и фактическая belief map S0-003 завершены 2026-09-17.

## P0 перед стартом task-веток

Устранить repository/bootstrap blocker:

- `code_root` по конфигурации — `Finni App`; в корне с governance-документами нет Git-репозитория;
- `integration_branch` задана как `dev`, но её наличие не подтверждено;
- до bootstrap Git/dev ветка `{task-id}/slug` не может быть создана так, чтобы включать governance-документы и код в один проверяемый change set.

Ни Git-ветки, ни GitHub-сущности в рамках этого запуска не создаются.

## Волна A — governance baseline

1. **S0-001** — подтвердить проектный governance и baseline без выдачи целевой архитектуры за фактическую реализацию. Это стартовая зависимость для S0-002 и S0-004.

## Волна B — подготовка в параллельных потоках

2. **S0-002** — после S0-001 выполнить `project-doctor` и вести только честную bootstrap-проверку. Её финальная стековая часть ожидает S0-005.
3. **S0-004** — после S0-001 зафиксировать M1 scope, владельцев, `applicationId`, ключ подписи и доступность внешних ресурсов. Она открывает S0-005.

S0-002 и S0-004 не должны редактировать один change set и могут идти в разных потоках после repository bootstrap.

## Волна C — главный runtime gate

4. **S0-005** — после S0-004 создать каркас Expo SDK 57 + React Native + TypeScript и получить первый release APK. Главный gate Sprint 0: APK устанавливается и запускается на Android API 26 без Metro.

На 2026-09-17 build, APK, подпись и статические проверки подтверждены, но
физическое устройство будет подключено позже. S0-005 закрыта как partial;
недостающая установка и запуск без Metro вынесены в **S0-006**. Это не отменяет
gate и не превращает статическую проверку APK в runtime PASS.

## Волна D — evidence из фактического кода

5. **S0-003** — после появления кода в S0-005 построить belief map из фактических модулей: full build, затем `search` и `analyze` для domain, persistence, content и UI.
6. **S0-002 (повторная стековая проверка)** — по появившемуся коду зарегистрировать лишь существующие lint, typecheck, test, content и fixture-команды и выполнить их.
7. **S0-006** — после подключения физического устройства установить текущий release APK на Android API 26 и подтвердить запуск без Metro.

S0-003 и повторная стековая часть S0-002 могут выполняться до подключения
устройства и параллельно друг другу. S0-006 остаётся обязательным финальным
runtime-gate Sprint 0. Belief map не создаётся из предположений или из одних
governance-файлов.

## Critical path

`P0 repository/bootstrap -> S0-001 -> S0-004 -> S0-005 partial -> (S0-003 и повторный S0-002) -> S0-006 runtime gate`

S0-002 может начать governance-часть сразу после S0-001, но закрыть её без evidence S0-005 нельзя. S0-003 не лежит раньше S0-005: её входом служит фактическая структура кода.

## Возможные параллельные потоки

- После P0: S0-001.
- После S0-001: S0-002 (project-doctor/bootstrap) параллельно S0-004 (scope и внешние ресурсы).
- После появления кода в S0-005: S0-003 параллельно S0-002 (стековое
  повторное Verify); S0-006 — после подключения устройства.

Один worktree допускает только одного пишущего исполнителя; параллельность возможна лишь при разделённых worktrees и несоприкасающихся файлах.

## Нельзя запускать как независимую работу

- Любую task-ветку до устранения P0 repository/bootstrap blocker.
- S0-002 до S0-001 и её стековое закрытие до S0-005.
- S0-004 до S0-001.
- S0-005 до S0-004: applicationId, подпись, владельцы и M1 scope не должны приниматься молча как допущения.
- S0-003 до появления фактического кода S0-005 или без full build карты.
- Закрывать S0-006 по статическому APK, эмулятору, API выше 26 или декларации
  доступности устройства.
- Final PASS, заменяющий runtime/external evidence mock-ом, заглушкой или непроверенной декларацией.

## Внешние и runtime evidence-gates

| Задача | Evidence для final PASS |
|---|---|
| S0-002 | Результат `project-doctor`; после S0-005 — существование и успешный запуск каждой зарегистрированной verify-команды, с честной фиксацией ненулевых exit codes. |
| S0-003 | Фактические manifest-файлы и модули; full build карты, `search` + `analyze` для четырёх областей, без worktrees/generated/cache/vendor. |
| S0-004 | Зафиксированные без предположений applicationId/teamSlug, владелец ключа подписи, доступность разработчика, Android-устройства и методического проверяющего, а также решение по M1 fallback. |
| S0-005 | Lockfile и закреплённые версии; clean release build; APK; установка и запуск на Android API 26 без Metro; отсутствие секретов/ключей в репозитории. |
| S0-006 | Физическое устройство с подтверждённым API 26; совпадающий SHA-256 APK; успешные ADB install, force-stop/start и process/foreground evidence без Metro. |

| S0-006 | Terra medium | Физический ADB-прогон детерминирован, но может потребовать диагностики device-specific установки или запуска. | Sol high только при реальном конфликте native/runtime требований. |

## Общий Definition of Done

- Выполнены критерии приёмки и Verify из task-файла; без completion evidence задача не помечается завершённой.
- Сохранены команды, версии, environment profile, raw runtime/external evidence и явные ограничения результата.
- Release APK для API 26 без Metro подтверждён как реальный запуск, а не только успешная сборка.
- После появления или структурного изменения кода belief map перестроена по фактическому `code_root`.
- Выполнены релевантные проверки и `git diff --check`, когда проверяемый change set находится в Git-репозитории.
- При изменении workflow, архитектуры или фактического поведения обновлены `IMPLEMENTATION_DECISIONS.md`, `CURRENT_IMPLEMENTATION.md` и релевантная Mermaid-диаграмма — либо явно зафиксировано отсутствие такого влияния.
