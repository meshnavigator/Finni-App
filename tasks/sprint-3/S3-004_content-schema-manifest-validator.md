# S3-004: Зафиксировать schema v3, manifest и валидатор контента

## Цель
Сделать восемь заданий версионируемыми данными, которые валидируются до сборки и не меняют старые результаты задним числом.

## Контекст
Учебный контент должен быть отделён от UI. Версии evaluator inputs, текстов и архивных попыток должны оставаться согласованными.

## Состав работ
- зафиксировать JSON schema v3 и outcome enum;
- создать content manifest с версиями и ссылками EDU;
- реализовать validator структуры, сумм, hints, вариантов и renderer IDs;
- сохранять snapshot версии/evaluation для завершённой попытки;
- подготовить восемь JSON и отрицательные fixtures.

## Источники
- официальное ТЗ, §§2.5.14, 3.2;
- SRS v1.3, §§13.11–13.13, 15.11;
- FR-23/61/63/64; DEV-21/46; TC-088, TC-174–182, TC-186/187.

## Критерии приёмки
- новое задание добавляется без изменения core UI;
- invalid content останавливает сборку;
- завершённая попытка не переоценивается новой версией;
- все 8 заданий имеют тему, уровень, наблюдаемое действие и объяснение.

## Зависимости
- S3-001–S3-003.

## Verify
- `validate:content` на positive/negative fixtures;
- tests version snapshot и archived evaluation;
- проверка manifest на циклические/битые ссылки.

## Out of scope
- удалённая CMS;
- загрузка контента из сети.
