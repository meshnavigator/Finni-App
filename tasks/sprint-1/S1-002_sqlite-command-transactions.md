# S1-002: Реализовать SQLite и атомарные денежные команды

## Цель
Обеспечить локальное транзакционное хранение журнала, проекций и `CommandReceipt` без частичных операций.

## Контекст
Профиль, деньги и прогресс должны переживать перезапуск; повтор команды не должен начислять или списывать средства дважды.

## Состав работ
- создать schema v1 с CHECK/UNIQUE/FK и журналом операций;
- реализовать очередь команд и атомарное обновление журнала, проекций, событий и receipt;
- обеспечить idempotency по `commandId` и бизнес-параметрам;
- разделить normal/demo базы и подготовить migration framework.

## Источники
- официальное ТЗ, §§2.5.13, 3.2, 3.4;
- SRS v1.3, §§15.1–15.5, 16.1–16.4;
- DEV-04; TC-062–070, TC-079/080.

## Критерии приёмки
- сбой до COMMIT не меняет ни одну проекцию;
- повтор после COMMIT возвращает прежний receipt;
- уникальные доход/награда защищены ограничениями БД;
- demo не читает и не пишет normal.

## Зависимости
- S1-001.

## Verify
- integration tests COMMIT/ROLLBACK/idempotency;
- повторное открытие SQLite и сверка журнала с проекциями;
- проверка обеих БД.

## Out of scope
- UI и календарные переходы;
- облачная синхронизация.
