# S2-005: Проверить транзакции, перезапуск и миграции ядра

## Цель
Подтвердить, что полный финансовый цикл сохраняется при повторе команд, остановке процесса, конфликте режимов и обновлении приложения.

## Контекст
Unit tests недостаточны для native SQLite и lifecycle. Это отдельный release gate, а не скрытая часть реализации экранов.

## Состав работ
- покрыть критические инварианты единым automated suite;
- проверить остановку до/после COMMIT и receipt;
- проверить переключение normal/demo и заполнение диска;
- подготовить migration fixture старой версии профиля;
- убедиться, что провал миграции не удаляет данные.

## Источники
- SRS v1.3, §§15.4–15.10, 18.1–18.5;
- DEV-14/22/28; TC-062–070, TC-079/080, TC-085/086.

## Критерии приёмки
- тесты денег, плана, награды, закрытия, роста и idempotency запускаются одной командой;
- crash points не создают частичные состояния;
- обновление тем же ключом сохраняет профиль;
- повреждение/ошибка сообщаются без тихого сброса.

## Зависимости
- S2-001–S2-004.

## Verify
- unit + SQLite integration suite;
- process-kill/migration fixtures на Android;
- повторная сверка журнала и проекций.

## Out of scope
- полная UI/performance-регрессия;
- миграция с реально выпущенной версии, которой пока нет.
