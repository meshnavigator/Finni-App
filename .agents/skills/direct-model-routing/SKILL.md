# Direct Model Routing

DIRECT — пользовательское назначение единственного исполнителя. Оно имеет
приоритет над любой автоматической маршрутизацией.

## Вход

Распознавай формы:

```text
DIRECT ASTRA HIGH: <задача>
DIRECT SOL XHIGH: <задача>
DIRECT SOL MEDIUM: <задача>
Только Luna: <задача>
Поручи Sol high: <задача>
```

Имена нечувствительны к регистру. `UNO` — совместимый псевдоним `LUNA`.
Канонические model IDs и значения reasoning бери из
`.project-kit/model-routing.json`, если файл доступен. Иначе используй:

- Astra → `gpt-6-astra`, default reasoning `high`;
- Sol → `gpt-6-sol`, default reasoning `high`;
- Luna/Uno → `gpt-6-luna`, default reasoning `high`.

## Ценовой шлюз Astra

Перед маршрутизацией или запуском Astra обязательно получи отдельное явное
подтверждение пользователя. Команда `DIRECT ASTRA ...` означает запрос на
использование Astra, но сама по себе не является подтверждением.

До запуска сообщи выбранный reasoning, краткую причину и scope, затем спроси:
`Разрешаете запустить Astra для этой задачи?` Не запускай Astra до ответа.
Подтверждение действует только для текущей задачи. При отказе останови DIRECT
без fallback на другую модель.

Если пользователь сам выбрал Astra основной моделью при создании открытой
задачи Codex, считай этот ручной выбор подтверждением для неё и не спрашивай
повторно перед каждым сообщением.

## Инварианты

- Ровно одна выбранная модель выполняет исследование, решения, реализацию и
  содержательную проверку.
- Не запускай adaptive routing, автоматическую эскалацию, fallback на другую
  модель, независимого reviewer или дополнительные агентские потоки.
- Не меняй явно указанное reasoning. Если оно не указано, используй default.
- Не подменяй недоступную модель или reasoning ближайшим вариантом.
- Обычные инструменты и детерминированные проверки не считаются другой моделью.

## Исполнение

Если текущий поток уже работает на выбранной модели с требуемым reasoning,
выполни задачу в нём без субагентов.

Иначе создай ровно одного агента с явно заданными `model` и `reasoning_effort`.
Передай ему исходный запрос и минимально необходимый контекст. Текущий поток
остаётся только диспетчером: он не меняет решение выбранной модели и не
проводит содержательное межмодельное review.

Если создать такого исполнителя невозможно, остановись и сообщи пользователю,
какая именно комбинация недоступна. Не выполняй задачу на другой модели.

Если одновременно указан запрет субагентов и текущий поток не совпадает с
выбранной моделью/reasoning, запроси одно уточнение вместо скрытого нарушения.

В итоговом ответе кратко укажи:

```text
EXECUTION_MODE: DIRECT
MODEL: <model id>
REASONING: <reasoning>
OTHER_MODELS_USED_FOR_CONTENT: NO
```
