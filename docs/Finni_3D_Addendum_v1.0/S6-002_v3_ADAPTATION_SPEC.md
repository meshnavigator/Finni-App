# S6-002 v3 — адаптивная спецификация Home/HUD

- Статус: **V3 FOR REVIEW**; макеты, не production UI и не runtime evidence.
- V2: **НЕ УТВЕРЖДЕНА**. V3 заменяет её только как следующий review candidate;
  файлы V1/V2 сохраняются как история.
- Scope: единая адаптивная система Home для `390×844` и `360×640` при
  `100%` и `200%` системного масштаба шрифта.
- Артефакты: `S6-002_HOME_HUD_MATRIX_v3.svg` и
  `S6-002_HOME_ACTIVE_DESIGN_v3.svg`.
- QA-статус: **QA-005 NOT RUN; QA-006 NOT RUN. PASS не заявлен.**

## 1. Решение V3

Home использует один и тот же порядок компонентов во всех четырёх комбинациях:

1. профиль/состояние периода;
2. финансовое резюме `Доступно + Копилка`;
3. текущая цель;
4. сцена с полнофигурным Финни;
5. care;
6. активный урок и отдельный переход к нему;
7. отдельный primary CTA следующего действия;
8. нижняя навигация `Домик / План / Покупки / Копилка`.

Первый viewport приоритетно показывает финансовое резюме и следующий шаг.
При `200%` уменьшается площадь сцены, но изображение Финни остаётся целиком и
не растягивается. Содержимое не прячется за icon-only controls, ellipsis,
`adjustsFontSizeToFit`, `minimumFontScale` или ограничением системного масштаба.

Scroll допускается только как fallback для достижения деталей. Он **не является
исключением** из требования ТЗ §2.5.3 об обязательной сводке. Если сводка не
видна одновременно, профиль получает статус `CONFLICT / review required`, а не
PASS. Именно так маркирован `360×640 / 200%`.

## 2. Четыре обязательные комбинации

| Viewport / scale | Сцена | Первый viewport | Статус review |
| --- | --- | --- | --- |
| `390×844 / 100%` | большая, Финни целиком | полная сводка, урок, отдельный CTA и active nav | `DESIGN CANDIDATE`; QA не запускалась |
| `360×640 / 100%` | компактнее, Финни целиком | финансы и следующий шаг видны; компоненты сохраняют порядок | `DESIGN CANDIDATE`; нужна runtime-проверка |
| `390×844 / 200%` | заметно уменьшена, Финни целиком | 32/40/48sp, финансы и CTA приоритетны; детали доступны продолжением | `REVIEW REQUIRED`; QA не запускалась |
| `360×640 / 200%` | минимальная допустимая, Финни целиком | финансы и CTA видны, но вся сводка §2.5.3 одновременно не помещается | **`CONFLICT / review required`** |

## 3. Единая типографика

Все значимые обычные UI-тексты имеют базовый размер не менее `16sp`.
Технические подписи вне телефона не являются интерфейсом приложения.

| Семантический token | 100% | 200% | Применение |
| --- | ---: | ---: | --- |
| `body / label / nav` | `16sp` | `32sp` | подписи, care, tabs, lesson |
| `title / CTA` | `20sp` | `40sp` | имя, заголовок действия, primary CTA |
| `amount / key value` | `24sp` | `48sp` | баланс, накопления, ключевая сумма |

Scale применяется согласованно ко всем label/button/nav. Line-height растёт
вместе с текстом; высота surfaces растёт или контент уходит в документированное
продолжение. Hit target каждого действия — не менее `48×48dp`, независимо от
визуального размера иконки.

## 4. Адаптивные правила

### 4.1. Порядок и fold

- Finance и primary CTA нельзя уводить оба ниже fold.
- Goal, care и lesson сохраняют семантику и порядок; в тесном профиле они могут
  продолжаться ниже fold, но это фиксируется как конфликт одновременной сводки.
- Bottom nav закрепляется только если не закрывает CTA или текст. Иначе nav идёт
  последним элементом scroll content; это также не превращает §2.5.3 в PASS.
- При уменьшении сцены используется `preserveAspectRatio="xMidYMid meet"`:
  персонаж не кадрируется, не деформируется и остаётся полнофигурным.

### 4.2. Приоритет высоты

Высота освобождается в порядке: декоративный воздух → высота сцены → внешние
отступы. Не уменьшаются системный текст, hit targets, финансовая информация и
следующий шаг. Финни может стать меньше при 200%, но не превращается в head-only
avatar и не обрезается по ушам, лапам или хвосту.

### 4.3. Safe areas

- верхний и нижний system inset учитываются отдельно от контента;
- постоянные HUD-surfaces не перекрывают полнофигурного Финни;
- модальный overlay блокирует scene/nav input и получает focus первым;
- технические safe outlines показываются только в отдельной панели/layer,
  никогда поверх polished-композиции.

## 5. Данные и честность статуса

### 5.1. READY — подтверждённый текущий baseline

Для READY источником остаётся таблица EV-01/EV-03 из
`S6-002_HOME_HUD_LAYOUTS_v2.md`: `Finni7`, `0 монет`, «Цель пока не выбрана»,
«Еда и уход — пока нет», «Начни день, чтобы открыть занятие», «Начать день» и
model-derived availability. Эти значения относятся к сохранённому текущему
2D runtime baseline, а не доказывают V3, 3D или доступность при 200%.

### 5.2. ACTIVE — проектные данные SRS

В polished ACTIVE-макете используется отдельный design fixture:

- `B=100`, `S=0` в начале первого дня;
- выбрана `GL-01` «Воздушный змей», цена `150`;
- доступен `LS-P02` «Покупки / детектив предложений»;
- primary action показан отдельно от перехода к уроку.

Источники: SRS v1.3 §§7.5, 13.1, 13.5, 19.2 и `TC-132`. На самом SVG
присутствует постоянная маркировка **`DESIGN DATA — NOT IMPLEMENTED`**.

Политика использования таких проектных данных — **PROPOSED / требует
согласования**. Это не Accepted-решение и не заявление, что runtime уже отдаёт
GL/LS/care fields. До реализации data contract разработка должна получать
значения из application model; макет не является fallback-источником данных.

Care показан как отдельная surface/route без выдуманного численного состояния:
лейбл «Еда и уход» и действие «Открыть план». Это сохраняет требуемую семантику,
не подменяя её недоказанным runtime-фактом.

## 6. Ordinary ACTIVE, `390×844 / 100%`

Polished Home содержит:

- крупную локальную сцену из `design/S6-002_v3_scene-preview.png`;
- Финни целиком, с сохранёнными пропорциями; preview является
  **reference-inspired ImageGen preview, not identity-preserving final art**;
- единый финансовый блок с tabular values;
- отдельную цель GL-01/150;
- отдельный care route;
- урок LS-P02 и его кнопку;
- отдельный CTA «Продолжить день»;
- active bottom nav с выделенным «Домик».

В SVG нет технического контура поверх polished phone. Safe silhouette, fold и
измерения вынесены в самостоятельную правую панель.

## 7. Accessibility и interaction contract

- TalkBack order: header → finance → goal → scene description → care → lesson
  → lesson action → primary CTA → nav.
- Динамическое изменение суммы/состояния объявляется один раз.
- Значение не кодируется одним цветом; active tab имеет shape, icon и label.
- Все суммы используют tabular numerals.
- Press feedback: только `transform: scale(.96)` и opacity при разрешённом
  motion; reduced motion оставляет сцену и controls статичными.
- Back закрывает keyboard/верхний overlay до навигации и не отменяет уже
  подтверждённую финансовую операцию.

## 9. Verify и открытые решения

До утверждения обязательны:

1. Android runtime-снимки всех четырёх комбинаций без font fitting;
2. проверка TalkBack order и 48dp targets;
3. крайние позы/анимации Финни в фактическом renderer;
4. решение product/design по конфликту `360×640/200%` без ослабления §2.5.3;
5. согласование **PROPOSED** policy для SRS design data и application-model
   contract ACTIVE.

V3 не доказывает renderer, performance, identity-preserving final art,
catalog/runtime implementation, `QA-005` или `QA-006`.
