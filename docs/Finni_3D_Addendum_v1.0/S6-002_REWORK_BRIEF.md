# S6-002 — brief переработки композиции Home/HUD

- Статус: **направление v2 для review; не runtime evidence**.
- Дата: 2026-09-18.
- Scope: M1 Home с одной комнатой, фиксированной камерой и полнофигурным
  Финни; `DEC-2026-09-18-002` остаётся принятым источником visual scope.
- Предыдущая поставка: `S6-002_HOME_HUD_LAYOUTS.md` и
  `S6-002_HOME_HUD_WIREFRAMES.svg` — **rejected baseline по композиции**.
  Их матрица состояний, данные, lifecycle-гейты и accessibility-ограничения
  сохраняются как материал следующей волны, но постоянные 2×2 HUD и маленькая
  сцена не передаются в разработку как основа Home.

## Нормализованная постановка

Построить Home вокруг единой комнаты и крупного полнофигурного Финни, сохранив
обязательную финансовую сводку и маршруты. Первое визуальное внимание должно
попадать на Финни, затем — на деньги и следующий шаг. Финни не является
иллюстрацией внутри карточки: его голову, уши, туловище, лапы, хвост и будущие
крайние разрешённые позы защищает **silhouette-safe zone**, а не один формальный
прямоугольник сцены.

Комната остаётся единственным непрерывным пространством. HUD допускается поверх
спокойных частей окружения, но не дробит Home на последовательность одинаковых
плиток и не закрывает тело персонажа. Референс `REF-001` задаёт приоритет
персонажа, воздуха и комнаты; суммы, предметы, подписи и кнопки из картинки не
являются данными.

Обычный макет v2 поэтому выбран как `READY`, а не как условный `ACTIVE`:
это единственное состояние Home с проверенными runtime-строками, которое можно
показать без выдумывания урока, каталожной цели или операции. После появления
реальных model fields/fixtures нужно создать `ACTIVE` на той же композиционной
основе.

## Принятые принципы композиции

1. **Комната доминирует.** На 390×844/100% сцена вместе с видимой комнатой
   занимает 520 dp (62% высоты); основной action dock начинается только после
   защищённой зоны лап/хвоста. HUD не делает фон «отдельной карточкой».
2. **Финни доминирует.** В ordinary Home контур персонажа занимает
   приблизительно 340×360 dp, а защищённая silhouette-safe zone не пересекается
   с постоянными HUD, целью, care chip, lesson/action dock и nav. Модальный
   overlay — единственное допускаемое обычное исключение.
3. **Деньги компактны, но читаемы.** `balance` и `savings` живут в одной
   двухсекционной панели; оба значения имеют подпись и текстовую сумму.
   Цель — отдельная строка, care state — короткий читаемый UI-элемент рядом с
   персонажем. Они не получают одинаковый визуальный вес.
4. **Два разных намерения.** Карточка активного занятия и 48 dp переход
   «Задания» — одна сущность. Primary CTA периода (`open-day`/`plan`/…) —
   другая. Они компактно собраны в нижнем dock, но не превращаются друг в друга.
5. **Навигация неизменна.** Нижние «Домик», «План», «Покупки», «Копилка»
   остаются четырьмя подписанными вкладками. `progress` и `adult` — отдельные
   текстовые 48 dp действия шапки, без нового постоянного раздела.
6. **Данные честны.** Используются только EV-01/EV-02 или явно маркированный
   token/gap. Не рисуются вымышленные `GL-*`, `LS-*`, покупки, сумма дохода,
   процент или настроение.

## Acceptance criteria

| ID | Проверка | Готово, когда |
| --- | --- | --- |
| RW-001 | Визуальная иерархия ordinary Home | На 390×844/100% комната читается единым пространством, Финни крупнее любой информационной поверхности и первым заметен при просмотре. |
| RW-002 | Защита Финни | В обычном Home постоянный UI не пересекает обозначенный контур ушей, глаз, туловища, лап и хвоста; доказательство — координаты/контур в SVG и последующий runtime review крайних поз. |
| RW-003 | Обязательная сводка | `balance`, `savings`, goal row, care state, lesson и primary action отображены как отдельные семантики; баланс и накопления — текстовые, подписанные, tabular. |
| RW-004 | Маршруты и намерения | «Задания» не запускают period CTA; period CTA не маскируется под урок. Сохранены plan/lessons/purchases/savings/progress/adult и четыре нижние вкладки без дубликатов. |
| RW-005 | Evidence data | Все нетокенные строки/суммы SVG имеют EV-01 или EV-02; catalog goal/lesson не выдуманы. Источник и gap отражены в layouts v2. |
| RW-006 | Hard mode | На 360×640/200% используются реальные размеры 40/32/24/48sp-equivalent и длинное допустимое имя. Если обязательные сведения не помещаются вместе с крупным Финни, SVG показывает fold и scroll continuation; это фиксируется как конфликт, а не PASS. |
| RW-007 | Доступность и polish после композиции | Hit areas ≥48 dp, safe insets, logical TalkBack order, concentric 24/16 radii, layered shadows, no color-only state, tabular numbers, `scale(0.96)` только при motion-enabled press. |
| RW-008 | Остальные состояния | `NO_PROFILE`, loading, error, DRAFT, ACTIVE, CLOSED, WAITING заданы в правилах следующей волны без новых визуальных frame. `NO_PROFILE` не показывает деньги, цель, урок или nav несуществующего профиля. |

## Правила следующей волны состояний

| Состояние | Правило на принятой v2-композиции |
| --- | --- |
| `NO_PROFILE` | Отдельная сцена знакомства/настройки внешности. Нет financial panel, goal row, урока, primary period CTA и финансовых tabs несуществующего профиля. |
| `loading` / `error` | Никаких подставных значений HUD. Loading блокирует scene input; error — модальный/retryable слой и после чтения не заявляет исход операции без `commandId`. |
| `DRAFT` | Композиция та же; primary CTA ведёт к плану, purchases/savings следуют прикладным read-only/availability правилам. |
| `ACTIVE` | Данные модели заменяют current placeholders; пользователь свободно открывает доступные уроки, покупки и накопления согласно lifecycle. |
| `CLOSED` / `WAITING` | Финансовые action gates берутся из lifecycle; не показывать придуманные таймеры, даты или доступный доход. |

| --- | --- |

## Необъявленные успехи и риски

- V2 не доказывает renderer, GLB, арт, animation poses, Android API 26 runtime
  или физическую производительность.
- `RW-006` намеренно выявляет конфликт `HUD-001`/`QA-005` с 360×640/200%,
  длинным именем и доминирующим персонажем. Решение о том, допустим ли scroll
  для части обязательной сводки, должен принять владелец продукта после
  интерактивного Android review; пока нельзя заявлять одновременную видимость
  всех обязательных полей в этом профиле.
- Текущие `careLabel`, `goalLabel`, `lessonLabel` — места, которые S6-001 и
  S6-002 v1 запрещали выдавать за завершённый функциональный контент. Их
  подтверждённые temporary strings здесь показаны только для композиционного
  evidence, не как принятый финальный контент.
